## 코드 검토 및 로컬 검증

`node --experimental-strip-types --test tests/study-cloud.test.mjs tests/study-storage.test.mjs tests/server-auth.test.mjs tests/release-quality.test.mjs` 결과 41/41 통과. 메모리 저장소/모의 의존성을 사용한 테스트가 포함되므로 실제 Firebase에서의 통합 테스트를 대체하지 않는다.

- 서버 학습 API는 검증된 토큰의 UID로 repository를 고정한다. 요청 body/query의 UID를 저장 경로로 사용하지 않는다.
- 브라우저 클라우드 캐시 키에 UID를 포함하고, 계정 전환 시 진행 중 응답을 무시하는 테스트가 통과했다.
- 카드 수정의 revision 충돌 검사, 오프라인 outbox 복원, tombstone 처리 테스트가 통과했다.
- 계정 삭제 API는 인증·5분 내 재인증·DELETE_MY_ACCOUNT 확인을 요구한다. UID는 토큰에서 가져온다.
- 삭제 함수는 계정에 삭제 잠금을 기록하고 Firestore 개인 하위 컬렉션을 삭제한 뒤 Auth 사용자를 삭제한다. account/status의 삭제 잠금 문서는 남는다. cleanupAfter 필드만으로 자동 삭제가 보장되지는 않는다. 실제 보관 정책 검토가 필요하다.
- 삭제 완료 응답 후 클라이언트는 signOut → 해당 UID 캐시 제거 순서로 실행한다. signOut 또는 localStorage 작업 실패 시 후속 정리가 중단될 수 있는 경로가 있다. 실제 발생은 관찰하지 못했다.

## 확인된 제한과 수정 제안

1. **잠금 대기 화면에서 복구 동작 부족.** 실제 배포 화면에서 다른 탭 종료 안내만 표시되는 상태를 확인했다. StudyProvider는 동일 UID Web Lock 획득을 기다리는 동안 학습 UI를 표시하지 않는다. 다른 탭에서 잠금을 보유한 경우에 맞는 설계이지만, 대기 화면에는 다시 시도·로그아웃·탭 위치 안내를 추가하는 것이 좋다. 다른 탭의 잠금을 강제로 빼앗거나 저장 중인 작업을 종료하는 수정은 피한다. 다른 탭을 정리한 뒤에도 대기가 지속되는지는 후속 확인 필요하다.
2. **계정 삭제 후 정리 실패에 대비.** 서버 삭제 성공 여부와 로컬 정리/로그아웃 결과를 구분하고, 로그아웃 실패에도 해당 UID 캐시 정리를 시도하도록 설계한다. 정리 실패 시 재시도 안내를 제공하고 실제 삭제 완료를 단순 실패로 표시하지 않게 한다. 오류 재현 및 회귀 테스트 후 적용할 사안이다.
3. **삭제 잠금 보관 정책 명확화.** account/status의 최소 메타데이터 잔존을 정책에 반영하고, 30일 후 정리가 필요하면 TTL/정리 작업을 별도로 설계·승인받는다. 현재는 자동 정리 설정 유무를 확인하지 않았다.

이번 작업은 앱 소스 수정, 실제 데이터 삭제, IAM 변경, GitHub push, 배포를 수행하지 않았다. 이 점검 문서만 로컬에 추가했다.
