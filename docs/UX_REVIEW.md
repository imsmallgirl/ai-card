# Moa UX 검토 및 개선 (2026-10-23)

## 기존 구현을 활용한 변경

- 자료 추출·AI 생성·직접 작성, 편집 가능한 미리보기, 저장 카드 선택, 같은 요청/덱 재시도는 기존 구현을 유지했다.
- 대시보드의 긴 소개와 사이드바/목표/배너 생성·복습 버튼을 정리했다. 상단의 오늘 복습과 카드 만들기를 핵심 행동으로 배치했다. 내 학습 덱의 생성 버튼과 빈 상태의 생성 버튼은 문맥에 맞게 유지한다.
- 실제 보유한 덱의 카테고리를 표시한다. 삭제 후 선택한 카테고리가 비어도 필터를 해제할 수 있게 현재 선택은 남긴다. 생성 화면의 전체 분류 선택지는 유지한다.
- 학습 경험 비율은 현재 카드의 완료 또는 평가 이력 기준이다. 복습 대기는 예정 시각 도래 카드 수이며 새 카드도 포함한다. 오늘 학습량은 새 세션의 반복을 포함한 완료 횟수다. 정확도와 구분한다.
- 키보드 건너뛰기 링크, 현재 메뉴 표시, 진행률 접근성 이름, 입력 안내 연결, 미리보기 선택 수 알림, 모바일 버튼/레이아웃/글자 크기를 보완했다. 기존 대화상자 포커스 처리도 유지한다.
- 자료 글자 수/AI 제한/예시와 단계 안내를 제공한다. 미리보기를 다시 추출할 때 수정·선택 교체를 확인한다. AI 결과 변환 후 임시 요청을 정리하도록 순서를 개선했다.
- 빈 추출/검색 결과/AI 실패/저장 실패 안내를 구분한다. 실패 시 기존 입력·결과·저장 요청 복구 기능을 유지한다.

로그인, Firestore 저장·계정 격리, 계정 삭제, GA4 동의/철회 및 환경변수 설정은 변경하지 않았다. 새 백엔드 API, IAM, Secret, 결제 설정은 추가하지 않았다.

## 아직 구현하지 않은 후보

아래 작업량은 설계·구현·회귀 검사를 포함한 대략적인 개발 시간이며 외부 승인/기기 검수 시간은 별도다.

| 우선순위 | 기능 | 예상 작업량 | 필요한 검토 |
| --- | --- | --- | --- |
| 높음 | 설정 내 도움말·동기화 문제 해결 안내 | 0.5–1일 | 기존 복구/동의 UI 연결, 중복 안내 정리 |
| 높음 | 덱 이름·분류 변경 | 1–2일 | 서버 명령/버전 충돌 처리 |
| 높음 | 전체 백업·복원 | 2–4일 | 스키마 검증, 사용자 구분, 중복 가져오기, 비밀값 제외 |
| 중간 | URL 기반 화면 이동·뒤로 가기·새로고침 복원 | 1–2일 | 인증/화면 이벤트 중복 검사, 민감 검색어 URL 제외 |
| 중간 | 덱 보관 | 1–2일 | 복습 대상/통계 포함 정책 |
| 중간 | 선택·전체 덱 삭제 | 2–4일 | 백업 선행, 동기화 대기 차단, 부분 실패/다중 기기, 통계 보존 범위 |
| 낮음 | 휴지통·복원 및 자동 영구 삭제 | 3–5일 | 보관 기간·서버 정리 작업·개인정보 정책 |

전체 삭제와 계정 삭제, 학습 기록 초기화는 별도 동작으로 설계해야 한다. 현재 덱 삭제는 서버에서 삭제 표시를 기록하므로 영구 데이터 삭제로 안내해서는 안 된다.

## 검증 범위

카테고리와 진행률 계산 회귀 테스트를 추가했다. 전체 단위/회귀 테스트, 타입 검사, 프로덕션 빌드, HTTP 검사와 브라우저 번들 비밀값 검사를 실행한다. 실제 로그인 사용자에 대한 운영 Firestore 쓰기·계정 삭제·Gemini 호출·GA4 수집은 실행하지 않는다.

실제 모바일 기기, 스크린리더, 브라우저 화면의 시각 검수와 운영 서비스 종단 간 검증은 이번 코드 검사만으로 완료됐다고 판단하지 않는다. 배포 전 추가 확인 항목이다.
