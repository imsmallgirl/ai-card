## 기존 기능에 영향을 주는 변경

로컬 authoritative 저장을 클라우드+대기큐로 전환, 배열 index를 cardId로 교체, 리뷰 boolean에 4단계/세션/revision 추가, 생성 즉시저장을 검토 후 저장으로 변경, 단일 `/` 화면전환을 공개·개인 라우트로 분리한다. 기존 원본·due/interval·날짜/성공 기록·로그인·검색/필터·통합/주관식 복습·스타일은 보존한다. 오래된 리뷰로 카드별 통계를 만들지 않는다.

## 설계 승인 기록

`~/Desktop/mvp/CARD_PLAN.md`의 Phase 2 지시: “이 단계가 끝나면 구현에 들어가기 전에 사용자에게 설계 결과를 요약하고 승인을 요청해.” 이후 사용자가 Phase 1·2를 승인하고 Firestore 동기화 작업만 진행하도록 요청했다.

승인 대상은 Firestore 카드별 문서+서버 쓰기, 원본보존 이관, 서버 한도3회/UTC 리셋/호출 후 실패 차감, 수정 시 일정초기화·이력보존, 네 단계 복습 규칙, 보존기간 제안이다. 현재 설계는 승인되었으며, 이후 작업은 사용자가 요청한 단위로 진행한다. 승인 자체는 클라우드 배포·과금 활성화·기존 데이터 삭제의 승인이 아니다.

출시 전 별도 확인: Firebase 리전/ADC/IAM·실제 Rules, Gemini 모델/요금제/개인정보 조건, 도메인·호스팅·예산·보존기간. 이번에는 어떤 콘솔 설정도 변경하지 않았다.


## 비로그인 랜딩·공개 안내 개편

사용자 우선 요청에 따라 CARD_PLAN.md 10절의 비로그인 공개 화면과 Phase 3 작업10 일부를 먼저 구현한다. 서비스 소개·기능·이용 방법·예시 카드 체험·FAQ·로그인·정책 안내를 공개하고, 개인 덱은 기존 인증 경계 뒤에 유지한다. 공유 기능 및 외부 광고는 포함하지 않는다. 정책 페이지는 운영 정보가 확정되지 않은 초안으로 명시한다.

기존 데이터 이관·카드 개별 추가/삭제 등 전체 CRUD·목적/난이도·4단계 복습·즐겨찾기·스트릭/캘린더·고급 통계와 광고 연동 준비는 여전히 후속 작업이다. 이번 화면 개편을 전체 CARD_PLAN 완료로 간주하지 않는다. 선택적 Analytics는 기존 코드만 보존하고 외부 수집을 활성화하지 않는다.

## 직접 학습 덱 만들기

사용자 요청으로 생성 모달에 AI/직접 만들기를 추가했다. 직접 입력한 질문·답 1~20장은 기존 계정별 저장과 확인/재시도 흐름을 사용하며 AI 사용량을 차감하지 않는다. 상단 저장 안내와 사이드바 스터디 스페이스 박스를 제거했다. 기존 카드 편집과 직접 생성은 구현되었지만 기존 덱에 개별 카드를 추가/삭제하는 전체 CRUD는 후속 범위다.

CARD_PLAN.md의 1~11번에 대한 구현을 반영했다. 최신 동작·정책·차이·남은 운영 설정은 [PHASE3_IMPLEMENTATION.md](PHASE3_IMPLEMENTATION.md)를 기준으로 확인한다. 앞선 “미착수/후속 작업” 표기는 당시 기록이다. Phase 4 품질 검증 및 Phase 5 출시는 별도이며 공유 기능은 제외한다.
