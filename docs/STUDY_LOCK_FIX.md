# 학습 저장소 잠금 및 삭제 후 정리 개선

같은 origin/UID의 캐시와 전송 대기열을 여러 탭이 덮어쓰지 않도록 exclusive Web Lock을 세션 동안 유지한다. 기존 화면에는 정상 잠금 대기에서 사용할 복구 버튼이 없었다. 또한 잠금을 얻기 전 legacy 저장소를 준비·검사하여 긴 대기 후 오래된 판단을 사용할 수 있었다. 어느 탭이 잠금을 소유했는지 또는 고아 잠금이 존재했는지까지 확인한 것은 아니다.

## 변경

- 대기·초기화 오류 화면에 재시도와 로그아웃을 추가했다. 재시도는 자신의 대기 요청만 취소하고 다시 요청한다. 다른 탭의 잠금을 빼앗거나 강제로 종료하지 않는다.
- 캐시 준비와 legacy 검사는 잠금 획득 후 수행한다. 세션 중단 후에만 lock callback을 종료해 소유권을 반환한다.
- 정상 로그아웃·재시도는 전송 대기열을 삭제하지 않는다. 같은 계정으로 다시 접속하면 기존 대기열을 읽는다.
- 중단된 세션은 지연된 동기화 응답이나 충돌 요청 폐기·legacy 조작 콜백으로 캐시를 다시 쓰지 못한다.
- 서버 계정 삭제 성공 후에는 세션 중단 → 해당 UID 캐시 정리 → 로그아웃 순서로 처리한다. 로그아웃 실패에도 캐시는 이미 정리되어 있다.
- 일부 키 정리 실패 시 나머지 키도 정리하며, legacy 삭제 실패 시 소유자 표식을 유지해 다른 계정이 이를 가져가지 못하게 한다.
- 정리 실패 시 마무리만 재시도한다. 서버 삭제 API는 재호출하지 않고, 재시도 시 다른 계정으로 바뀌었다면 해당 계정을 로그아웃시키지 않는다.

## 검증

전체 로컬 테스트 144개, 타입 검사, 프로덕션 빌드, 브라우저 번들 비밀값 검사 통과. Node 24의 실제 Web Locks로 대기 취소·재시도·소유권 유지·초기화 실패 후 반환을 검증했다. 모의 로그아웃 실패·저장소 오류·지연 응답으로 다른 UID 보존과 캐시 재생성 차단을 확인했다.

추가 로컬 HTTP 검사는 포트 실행 권한 승인 대기 단계에서 중단하여 이번 변경에 대해 재실행 완료로 기록하지 않는다. 실제 브라우저의 두 로그인 탭 및 새 UI 클릭, 실제 Firebase 계정 삭제 후 흐름은 미검증이다. 실제 계정 삭제, IAM 변경, push, 배포는 수행하지 않았다.
