## 데이터 이전 정책

`LegacyMigration`의 버튼을 사용자가 누르면 시작한다. 이 작업을 개발한 것만으로 운영 데이터가 자동 이전되지는 않는다. 현재 계정의 Firebase ID 토큰을 사용하는 기존 `/api/study`로만 접근한다. UID를 본문에서 받지 않는다.

- 로컬 원본 `moa-study-user-{uid}`와 첫 이전 백업 `moa-study-import-backup-{uid}`는 삭제하지 않는다.
- 이전 중 기존 데이터가 변경되면 완료 처리하지 않는다. 같은 원본으로 재시도할 수 있으며 다른 원본 내용이 같은 대상에 들어오면 충돌을 표시한다. 충돌한 원본을 임의로 덮어쓰거나 합치지 않는다.
- 서버 `decks.importSource`, 안정적 mutationId 및 `legacyImports/day-{date}`로 동일 원본의 중복 생성/통계 증가를 막는다. 동일 요청 재전송은 기존 mutation 결과를 반환한다.
- 전송 중인 덱은 `importing:true`로 숨긴다. 카드 수 검증 후 `finishImport`로 공개한다. 병합 화면은 원본 덱 식별자와 이전된 일별 기여량을 사용해 중복 표시/집계를 방지한다.
- 질문/답/생성일/순서/due/interval 및 존재하는 즐겨찾기·카드별 집계를 복사한다. 날짜별 기록은 원래 날짜를 유지한다. 원본 카테고리가 현재 목록에 없으면 기타로 분류하며 원본은 로컬에 보존한다. 허용 길이/형식에 맞지 않는 원본은 자동 절단/삭제하지 않고 전체 이전 전에 오류를 표시한다.
- 날짜·성공 여부만 있는 옛 기록으로 카드별 오답이나 카테고리 이력을 만들어 내지 않는다.
- 여러 기기에 서로 다른 로컬 원본이 있는 경우 자동 병합하지 않는다. 동일 덱/같은 날짜 집계의 내용이 다르면 충돌 해결이 필요하다.

## 학습 및 편집 정책

다시=1분, 어려움=이전 간격 1.2배 올림(최소1일), 기억함=2배(최소1일), 쉬움=3배 올림(최소3일). 간격 상한100년. boolean 과거 평가도 기억함/다시로 해석한다. 어려움/기억함/쉬움은 성공으로 집계한다. 규칙 모듈은 FSRS 구현과 분리된 교체 지점이며 FSRS를 구현했다고 표시하지 않는다.

내용 수정은 해당 카드 due/interval을 초기화한다. 기존 reviewEvents와 일별 집계, 누적 카드별 횟수는 유지한다. 수정 폼에서 읽었던 원본 revision을 사용해 다른 기기의 변경을 덮어쓰지 않는다. 카드 삭제는 tombstone이며 마지막 한 장은 개별 삭제할 수 없고 덱 삭제를 사용한다. 생성/초기 직접 생성은 1~20장, 기존 덱에는 최대2000장까지 추가할 수 있다. 서버 요청 본문64KiB 한도는 별도로 적용된다.

Space는 뒤집기, 1~4는 평가, 좌우 방향키는 탐색이다. 입력/선택/버튼/편집 가능한 요소에서 단축키를 가로채지 않는다. 이미 평가한 카드는 같은 세션에서 다시 평가하지 않으며 탐색/건너뛰기는 평가를 저장하지 않는다. 완료 화면은 실제 평가 수만 집계한다. 서버 revision과 mutationId가 중복 쓰기를 추가로 차단한다.

목표/타임존 변경은 새 기록부터 적용하고 과거 날짜를 재해석하지 않는다. 스트릭은 오늘 또는 어제까지 이어진 양수 학습일이며, 캘린더/학습량은 고유 카드 수가 아닌 평가 횟수다. 카테고리 통계와 오답 상위 카드는 현재 남아 있는 카드에 실제 저장된 기록만 사용한다.

## AI 생성 흐름의 변경

이전 자동 덱 저장에서 **생성 → 검토 → 명시적 저장**으로 바뀌었다. 서버에는 실패 복구용 원본 결과가 보존되지만 `/api/study`의 학습 덱은 저장 버튼을 누를 때 생성된다. 검토 내용은 기존 계정별 pendingGeneration 키에 보존되며 새로고침 후 재개한다. 저장을 시작하면 편집을 잠그고 동일 덱 ID로 재시도한다. 검토/저장은 AI를 다시 호출하지 않는다.

개별 재생성은 기존 카드의 개념을 참고 자료로 사용해 count=1을 요청한다. 원래 카드 ID/revision을 보존하고 검토 후 같은 카드에 반영한다. 생성 실패 후 새 요청 준비에서도 대상 카드 연결을 유지한다. 다른 기기에서 원래 카드가 변경되면 결과를 자동 덮어쓰지 않는다. 정규화 후 동일한 AI 질문은 오류로 거절하며 API를 자동 재호출하거나 Mock으로 대체하지 않는다. 의미 수준의 중복 판정/사실 검증을 보장하지 않는다.

## 검증과 남은 출시 작업

최종 실행 결과는 TESTING.md의 이번 항목에 기록한다. 실제 Gemini 호출·운영 Firestore 쓰기·광고 활성화·클라우드 배포는 실행하지 않았다. 브라우저의 실제 로그인/개별 재생성/모바일 터치 전체 E2E는 아직 별도 검증이 필요하다. Phase 4의 접근성/성능/반응형 종합 검증과 Phase 5의 계정 삭제/정책 확정/모니터링/배포는 완료로 간주하지 않는다.

운영 도메인이 확정되면 SITE_URL을 설정해야 한다. 정책 페이지는 계속 초안이다. 실제 광고 연동은 계정·광고 단위와 당시 정책 및 동의 절차 확인 후 별도 작업이며, 준비 단계에서 광고가 실제로 표시되지는 않는다.
