# 자료 기반 카드 생성

## 구현 전 구조와 변경 방향

프로젝트는 Next.js 16.4.2 / React 19.3.1이다. 로그인 후 `StudyApp`이 생성 모달과 학습 화면을 관리한다. 기존 생성 방식은 AI/직접 입력 두 가지였고, 카드는 질문·답·복습 일정 및 선택적 학습 집계를 저장했다. Google 로그인은 AuthProvider, 서버 인증은 Firebase Admin의 ID 토큰 검증을 사용한다. Zustand의 계정별 cloud store가 인증된 `/api/study`를 호출하고 서버가 `users/{uid}/decks`, `users/{uid}/cards`를 쓴다. 기존 Gemini 생성은 `/api/generate`, 서버 일일 한도/동시 요청/중복 방지, 검토 후 저장 흐름을 사용한다.

이번에는 기존 구조를 교체하지 않고 자료 파서와 모달을 분리했다. 새 카드 속성은 모두 선택 사항이라 기존 카드에 데이터 마이그레이션이 필요하지 않다. 카드 생성과 편집, 클라우드 검증·저장·재조회, 복습 렌더링에 같은 해설/분류 스키마를 연결했다.

## 세 가지 생성 방식

1. **자료로 만들기(기본)**: 자료 입력 → AI 없이 추출 → 원본 비교·수정/제외 → 최종 저장. 일반 새 덱 만들기 진입점은 이 방식을 연다.
2. **AI 자동 생성**: 기존 제목/카테고리/목적/난이도/참고 자료 생성 흐름을 유지한다. AI API 키는 서버에서만 사용한다.
3. **직접 만들기**: 기존 질문·답 직접 입력을 유지한다.

기존 보라색 모달/버튼/입력 스타일과 모드 선택 그룹을 재사용했다. 모드 전환은 진행 중이 아닐 때 가능하며 전환 중에는 입력을 유지한다. X 또는 배경 클릭으로 생성 창을 닫으면 세 가지 방식의 입력·미리보기·임시 AI 요청 연결을 초기화한다. 이미 저장된 카드와 서버 작업, Firestore 전송 대기 요청은 삭제하지 않는다. 저장 전 자료 초안은 새로고침하면 사라질 수 있다. 저장된 덱은 기존 Firestore/계정별 동기화로 유지한다.

## 규칙 기반 추출

`material-parser.ts`는 fetch/SDK/API 의존성 없이 브라우저에서 실행한다.

지원 예:

```text
1. React의 특징은?
답변: 컴포넌트 기반 UI입니다.
-> 재사용성과 선언적 UI가 학습 포인트입니다.

Q2: 상태란 무엇인가요?
A2: 컴포넌트가 기억하는 데이터입니다.
```

```markdown
# 면접 노트
## 1. React란 무엇인가요?
### 답변
UI 라이브러리입니다.
### 학습 포인트
컴포넌트에 주목합니다.
```

번호(1./1)/(1)/①), Markdown 제목, Q:/Q1:/질문:/문제:, A:/A1:/답변:/정답:/정답 ;/답:, 별도 줄의 ->/→/해설:/추가 설명:/학습 포인트:/풀이:를 지원한다. 답변의 줄바꿈·목록·코드 블록은 보존하고 질문 경계를 코드 블록 안에서 찾지 않는다. 원문의 표지 문법과 바깥 공백을 제거할 뿐 질문/답을 요약하거나 다시 쓰지 않는다.

질문마다 한 카드를 만든다. 답이 없으면 빈 답과 경고를 표시하며, 답을 입력하거나 해당 카드를 제외하기 전에는 저장할 수 없다. 제목·도입부처럼 카드에 들어가지 않은 줄, 애매한 번호 목록도 경고한다. 아무 문장에서나 답을 지어내지 않으며 경계를 찾지 못한 비정형 자료는 원문을 형식에 맞게 정리하거나 선택적 AI 분석을 사용할 수 있다. 모든 문서 형식을 완벽히 인식한다고 보장하지 않으며 저장 전 원본 비교가 필요하다.

분류는 현재 카테고리 목록을 사용하는 키워드 규칙이다. 문맥과 단서를 바탕으로 태그·난이도를 보수적으로 추정하고, 근거가 없거나 동률이면 기타/미지정으로 둔다. 덱 카테고리와 카드별 카테고리/태그/난이도를 사용자가 수정할 수 있다. 카드는 포함 체크박스로 제외/재포함한다.

## 데이터 모델과 저장

공통 `card-content.ts`:

- question: 1~500자, answer: 1~2000자.
- explanation?: 최대4000자, 별도 해설/학습 포인트.
- category?: 기존 STUDY_CATEGORIES 값. 명시적으로 해제한 경우 null.
- tags?: 최대8개, 태그당1~40자.
- difficulty?: 초급/중급/고급. 명시적으로 해제한 경우 null.

기존 카드의 선택 필드가 없어도 정상 조회/복습한다. 자료 카드는 최종 확인 후 기존 인증 API로 저장한다. 일반 생성 명령은 최대200장까지 받도록 확장하되 AI와 직접 입력의 기존 20장 상한은 유지했다. 자료는 최대60,000자/200개 질문, 저장 본문은 기존64KiB 한도다. 초과하면 자동으로 자르지 않고 제외 또는 분할 저장을 안내하며, 용량 오류 전에 입력을 잠그지 않는다.

저장 시작 시 고정된 material-UUID 덱을 보존하고 같은 저장 요청으로 재시도한다. 클라우드 outbox/transaction 멱등성/UID 격리를 그대로 사용한다. 실패한 저장의 입력을 유지하며 중복 클릭은 잠근다. 자료 원문 전체를 학습 덱에 별도 저장하지는 않고 선택한 질문·답·해설·분류를 저장한다.

저장한 해설은 카드를 뒤집은 뒤 정답과 함께 표시하고 카드 수정에서도 변경할 수 있다. 질문·답·해설을 바꾸면 해당 복습 일정만 초기화하고 과거 기록은 유지한다. 분류·태그만 바꾸면 기존 복습 일정도 유지한다. 즐겨찾기/위아래 이동 및 어려움/쉬움 UI는 다시 추가하지 않았다.

## AI 비용과 실패 처리

자료 모달 진입·규칙 추출·규칙 분류·미리보기 편집에는 Gemini를 호출하지 않고 사용량도 차감하지 않는다. 카드 저장에는 기존 Firestore 읽기/쓰기가 발생할 수 있으며 이는 AI API 비용과 별개다.

사용자가 「AI로 카드 추출하기」 영역에서 자료 전송·AI 사용량 차감을 확인하고 AI 버튼을 누른다. 이때만 기존 `/api/generate`에 mode=material로 요청한다. 서버 인증/횟수 제한/동시 요청/타임아웃/오류 처리와 모델 설정을 그대로 사용한다. 요청 ID는 별도 계정별 `moa-material-ai-pending-{uid}`에 보존하고 이전 결과를 조회해 중복 호출을 방지한다. 실패는 자동 Mock 대체나 자동 새 생성으로 바뀌지 않는다.

AI 분석은 최대15,000자/20장이다. 규칙으로 이미20개를 넘는 질문을 인식하면 API 호출 전에 무료 추출/자료 분할을 안내한다. AI 추출 성공 시 기존 규칙 추출 카드와 사용자 수정·제외 상태를 모두 AI 결과로 교체한다. 모든 AI 자료 카드에는 유효한 카테고리·1~8개 태그·난이도가 필요하며, 누락되면 실패로 처리하고 이전 미리보기를 보존한다. AI 결과가 원문의 사실이나 의미를 검증했다고 표시하지 않는다. Mock 모드 결과는 실제 분석이 아님을 표시한다.

AI 실패 시 기존 미리보기와 원본을 보존하며 규칙 기반 추출 버튼은 다시 사용할 수 있다. 손상된 AI 복구 정보는 AI 새 요청만 잠그고 무료 추출은 잠그지 않는다. 개인정보·비밀키·자료 전문은 로그에 추가하지 않았다. 외부 수집/광고를 활성화하지 않았다.

## 객관식 자료 붙여넣기

- `1. 산소 2. 수소 ...`, `1번, 단백질 2번, 당분 ...`, `① 하나` 형태의 보기를 질문에 보존합니다.
- 줄 끝에 이어진 `정답 : 4, 수분`과 별도 줄의 `정답 : 4. 이산화탄소`를 정답 필드로 분리합니다. 정답 번호와 원문 내용은 유지하며 정답이 없으면 추측하지 않습니다.
- 명시적인 A:/답변: 이후의 번호 목록은 기존처럼 답변에 남깁니다. 해설은 별도 필드에 보존합니다.
- AI 분석 프롬프트에도 보기/정답 분리 지침을 적용했습니다. 규칙 기반 추출에는 AI 호출이 없습니다.
- 사용자가 제공한 33~35번 예시 및 줄별 보기/정답 누락 사례를 회귀 테스트로 검증했습니다.

## AI 작업 중 화면 잠금

AI 자동 생성·자료 추출·카드 재생성에는 공통 `AiLoadingOverlay`를 사용한다. 생성 팝업 내부에만 블러와 회전 스피너를 표시한다. 팝업 내부 컨트롤을 inert로 잠그고 클릭·Tab·Escape 조작을 차단한다. 팝업이 스크롤된 위치와 크기에 맞춰 로딩 영역을 배치하며 팝업 스크롤만 잠근다. 대시보드에는 추가 블러를 적용하지 않는다. 성공·오류·컴포넌트 정리 시 해제하며 포커스와 스크롤을 복원한다. 저장 완료를 기다리는 기존 생성 흐름에도 같은 잠금을 적용한다.

AI 카테고리는 응답 스키마의 enum으로 기존 18개 분류 중 하나만 허용한다. 자료 추출에는 이전에 선택된 덱 카테고리를 정답처럼 전달하지 않고 원문 기준 분류를 요청한다. 화학은 별도 최상위 카테고리가 아니므로 「과학」으로 선택하며 세부 주제는 태그에 담을 수 있다.

## 정답 없는 객관식과 덱 이름

규칙 추출은 명시된 답만 옮기며 정답 없는 문항을 풀지 않는다. AI 추출은 정답이 없는 객관식을 확립된 지식으로 풀이하도록 요청하고, 추론한 답은 해설에 「AI 풀이」와 근거를 표시하도록 지시한다. 자료의 명시적 정답은 우선 보존한다. 모델의 정답 정확성을 보증하지 않으며 저장 전 검토가 필요하다.

AI 응답의 title을 필수 검증하고 서버 draft·재조회 응답·클라이언트를 거쳐 학습 덱 이름에 자동 반영한다. 기존 응답 호환을 위해 공통 응답의 title은 선택 필드다. 원문에서 규칙으로 질문 경계를 인식하면 문항별 경계 안내를 AI 요청에 추가하고, 결과 카드 수가 다르면 MATERIAL_QUESTION_MISMATCH로 실패시켜 기존 미리보기를 보존한다. 실패 뒤에 자동 추가 호출은 하지 않는다.

40~42번 제공 예시로 원문 3문항 분리·여러 줄 보기·세미콜론 정답을 검증했다. 가짜 AI 응답을 이용해 제목 저장/재조회와 2장으로 병합·누락된 결과 거부를 검증했으며, 실제 Gemini 풀이 품질 검증이나 비용이 발생하는 호출은 하지 않았다.

## 평가 없는 학습 화면

학습 화면은 질문/정답/해설, 현재 카드 번호, 이전/다음 및 종료 버튼만 표시한다. 주관식 모드의 답안은 세션 화면에서만 비교하며 저장하지 않는다. 기억 평가 UI·성공률·다음 복습일·복습 키보드 단축키를 제거했다. 카드 뒤집기에서 평가 API를 호출하지 않는다. 다음 카드/학습 마치기에서는 별도의 학습 완료 명령으로 진행률·학습량·스트릭을 갱신하며 기억 평가값이나 복습 간격은 변경하지 않는다. 기존 저장 기록과 서버 호환 API는 유지한다.

## 학습 완료와 진행률

- `다음 카드`/마지막 `학습 마치기`는 현재 카드의 완료를 저장한 뒤 이동한다. 같은 세션에서 이전 카드로 돌아가도 카드별 한 번만 집계한다. 마지막 완료 저장이 실패하면 완료 화면으로 이동하지 않고 같은 ID로 재시도한다.
- 카드의 `completedAt`·`studyCount`와 평가 없는 완료 이벤트를 저장한다. 이벤트에는 correct/rating이 없으며 날짜별 통계의 count/completed를 증가시킨다. 이전 평가의 correct 집계와 구분하므로 완료를 오답으로 집계하지 않는다.
- 덱 진행률은 완료된 카드 비율이며, 기존 데이터의 interval>0도 학습 이력으로 인정한다. 질문·답·해설을 바꾸면 해당 카드의 완료 상태를 초기화하고 분류 변경은 유지한다. 카드를 새로 추가하면 새 카드도 완료해야 100%가 된다.
- Firestore 명령의 mutationId로 응답 유실·재시도에 따른 중복을 차단한다. 로컬 완료도 같은 ID를 재집계하지 않는다. 기존 UID 경계와 outbox를 사용한다. 로컬 기록의 클라우드 이전에서도 평가 없는 완료 기록을 보존한다.
- 새 완료는 오늘의 학습 목표·캘린더·스트릭에 포함한다. 통계 화면의 기억 성공률 대신 누적 학습량을 표시한다. 기존 복습 일정과 평가 데이터는 호환 목적으로 유지한다.
- 검증: 일반 테스트 128개, 로컬 Firestore 에뮬레이터 테스트 10개, 타입 검사·프로덕션 빌드 통과. 실제 운영 데이터 변경이나 Gemini 호출은 하지 않았다. 브라우저의 실제 조작 검증은 수행하지 않았다.

## 완료 화면과 하루 목표 설정

완료 화면은 이번 세션에서 완료한 카드 수·오늘 학습량·하루 목표 진행률을 표시하고, 대시보드 복귀와 같은 카드 다시 학습하기를 제공한다. 다시 학습은 새 세션으로 집계하므로 이전 세션 내 중복 방지 ID를 초기화한다.

하루 목표 기본값은 20장이다. 대시보드의 목표 변경에서 10/20/30장 빠른 선택 또는 1~1,000장 정수 입력 후 저장한다. 기존 updateSettings 경로로 현재 타임존을 보존해 저장하며 새로고침/다시 로그인 후에도 유지한다. 설정 화면에서도 변경 가능하다.

달성률은 오늘 완료한 카드 수 / 저장된 하루 목표 * 100이며, 반올림하고 최대 100%로 표시한다. 같은 세션 내 재방문은 중복 집계하지 않지만 새 세션에서 같은 카드를 다시 완료하면 학습량에 포함된다. 오늘의 날짜는 계정 타임존을 사용한다. 설정 화면의 오래된 다시/기억함 평가 안내도 현재 완료 방식에 맞춰 교체했다.
